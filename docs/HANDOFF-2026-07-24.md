# Handoff - 2026-07-24

Multi-channel Flue support agent. This doc lets a fresh session continue without re-deriving state.
Design + rationale live in `docs/flue-support-agent-plan.md` - read that first; this handoff only covers what changed and what is missing.

## Where the project actually is

**Parts exist; nothing is assembled end to end.** An autonomous Ralph run built the code skeleton overnight (see commit history: `feat(convex)`, `feat(agent)`, `feat(web)` commits by `Ralph Wiggum`). The gate is green - but green proved only that it compiles, not that it works.

What is built and typechecks:
- Convex data layer: `orders`, `tickets`, `outbox` tables + functions (`packages/backend/convex`)
- Tools: `createSupportTools(id)` + `lookup_order_status` + guarded `send_reply` (`apps/agent/src/shared/support-tools.ts`)
- Agent: `defineAgent` + web-lane HTTP `route` (`apps/agent/src/agents/support-assistant.ts`)
- Web: `/support` chat page composing `packages/ui` chat primitives (`apps/web/src/app/support`)

## The load-bearing gap (job #1 for next session)

**The wiring was never exercised.** Ralph's tests cover only pure functions (status mapping). No test seeds a row, runs a real Convex query/mutation, or renders a component. The `orders`/`tickets`/`outbox` tables are **empty**. So "the DB connects to the app" rests entirely on the code compiling.

Concrete proof this matters: a lint-passing change shipped a `<label>` that **crashed at first render** (fixed this session - see below), and no gate caught it because `packages/ui` has no render tests.

**Do first:** seed data + integration tests that actually run the Convex functions and assert results; a render test for UI components; then wire the pieces so `/support` reaches a running agent. (This is the "Green gates lie" lesson now baked into the `create-container` skill.)

## Also not built (deliberately, or human-gated)

- Inbound WhatsApp channel (`apps/agent/src/channels/twilio.ts`) - dispatches Twilio webhooks to `id = whatsapp:+1…`. Not written.
- A live-run script for the agent (`flue dev`/`flue run`) - the agent is defined + typechecked, never run against a model.
- No LLM eval harness (intentionally - no `ANTHROPIC_API_KEY`, cost).
- Deploy: agent needs a long-lived host, web needs hosting, Convex is already cloud.

## Decisions / corrections locked this session

- **Hosting: put the agent AND the Next app on one platform (Railway/Fly).** The earlier plan split web→Vercel; that split is unnecessary. Simpler on one host.
- **Better-Auth is a library**, not a service. `BETTER_AUTH_SECRET` is a local signing key you generate (set via `convex env set`), not an account/API key.
- **Convex is a document DB** - no foreign keys, so no relationship lines in its dashboard. Relations are by `v.id("table")` convention.
- **No LLM evals** in this build (cost). Verification is unit + (missing) integration tests.
- The `create-container` skill now lives in `~/.agents/skills/create-container` (moved from `~/.claude/skills`, symlinked to all harnesses) with the lessons from this run: stall guard, `grep -c` fix, caffeinate toggle, `RALPH_SCOPE.md` checklist, "green gates lie."
